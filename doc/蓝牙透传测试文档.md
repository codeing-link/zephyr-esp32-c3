# ESP32-C3 蓝牙透传测试文档

本文用于复现已完成的 UART、手机 BLE 和 macOS 蓝牙串口闭环测试。测试基准固件为本工程当前版本，测试状态截至 2026-07-15。

## 1. 验证结论

|测试层级|结果|说明|
|---|---|---|
|GPIO8 与 USB 启动日志|通过|状态灯每秒翻转，日志可在复位后完整捕获|
|UART AT 自动测试|14/14 通过|脚本记录见 [AT指令测试记录.md](AT指令测试记录.md)|
|nRF Connect 双向透传|通过|扫描、连接、订阅和 20 字节双向透传已验证|
|macOS 蓝牙串口闭环|自动项目全部通过|含 BLE→UART 150 字节长写，记录见 [macOS 测试记录](../function_test/macos_ble_test/macos_ble_test_record.md)|

软件复位和自定义 MAC 是破坏当前连接或永久修改身份的操作，不纳入 macOS 自动化；其人工验证步骤见第 6 节。

## 2. 测试前准备与接线

- 将最新固件烧录到 ESP32-C3。
- USB-C 连接电脑：`/dev/ttyACM0` 用于烧录和查看启动日志。
- USB 转串口模块用于 AT 指令和 UART 透传。Linux 常见设备名为 `/dev/ttyUSB0`，macOS 常见设备名为 `/dev/cu.usbserial-*`。
- UART0 默认参数：115200、8N1、无流控。
- 手机安装 nRF Connect for Mobile，用于手机端 BLE 测试。

|ESP32-C3|USB 转串口模块|说明|
|---|---|---|
|GPIO21 / UART0 TX|RXD|模块向电脑发送数据|
|GPIO20 / UART0 RX|TXD|电脑向模块发送数据|
|GND|GND|必须共地|
|USB-C|电脑 USB|仅用于烧录和 USB 日志，不接 USB 转串口模块|

GPIO8 接运行状态 LED；不要将 USB 转串口模块的 5 V 电平直接接入 ESP32-C3 GPIO。

## 3. 启动日志与状态灯

烧录时必须先关闭日志监听，避免 `/dev/ttyACM0` 被占用：

```bash
bash ./zephyr-remote-flash.sh
bash ./catcom.sh
```

按开发板 `RST`。USB 串口会短暂断开约 1 秒，`catcom.sh` 会自动重连；应用又会等待 2 秒才初始化硬件，因而不会丢失应用层首条日志。关键日志为：

```text
应用启动延时结束，开始初始化 GPIO8 状态灯
GPIO8 初始化完成，开始每 1000 ms 翻转一次
BLE 透传服务已启动：FFF0/FFF3/FFF4
```

同时确认 GPIO8 LED 每 1000 ms 改变一次亮灭状态。

## 4. Linux UART AT 自动测试

断开所有 BLE 中央设备后，在 Ubuntu 工程目录执行：

```bash
cd /home/qinbo/mpushare/macos_workspace/zephyr/apps/esp32-c3
python3 function_test/test_at_commands.py --port /dev/ttyUSB0
```

脚本覆盖 14 个安全的查询、设置与错误处理项目，并生成 `doc/AT指令测试记录.md`。运行后应显示 `总计：14/14 通过`。如果无串口权限，请将用户加入 `dialout` 组并重新登录。

测试会改变名称、产品 ID、广播周期、数据延时和附加广播内容。按 RST 后再次查询 `REN`、`ADD`、`MAC`，确认需保存的参数仍有效。若首次升级日志提示旧 NVS 配置无效，固件会恢复出厂默认值；重新设置一次即可建立新格式配置。

## 5. 手机 nRF Connect BLE 测试

1. 扫描设备，确认能看到 AT 设置后的广播名称。
2. 连接设备，展开主服务 `0xFFF0`。
3. 为特征 `0xFFF4` 打开 Notify。
4. 向特征 `0xFFF3` 执行 Write 或 Write Without Response，发送 `HelloBLE`。
5. 在 UART 串口终端确认收到 `HelloBLE`。
6. 在 UART 串口终端发送 `HelloUART`，确认 nRF Connect 在 `0xFFF4` 收到相同内容。
7. 保持连接时发送 `TTM:CIT-100ms`，应收到 `TTM:OK`；断开 BLE 后再发送同一命令，应收到 `TTM:ERP`。

默认 MTU 为 23，因此未协商时每个 ATT 包仅含 20 字节有效数据。需要更长数据时，中央设备应请求 153 字节 MTU，或按“当前协商 MTU - 3”自行分包。

## 6. 15 类 AT 指令核对

UART 会先原样回显命令，再输出结果。下表给出主要期望；设置类命令除特别注明外需在未连接状态执行。

|序号|命令|预期结果与验证重点|
|---:|---|---|
|1|`TTM:BPS-115200`|先返回 `TTM:OK`，再切换波特率；掉电不保存|
|2|`TTM:RST-SYSTEMRESET`|返回 `TTM:OK` 后重启；重新枚举并确认启动日志|
|3|`TTM:VID-?`|返回 `TTM:VID-LSD_BLE_5.0`|
|4|`TTM:REV-?`|返回 `TTM:REV-V2.1`|
|5|`TTM:CDL-5ms`|返回 `TTM:OK`，复位后保持；本板未接 BCTS，无法测量硬件时序|
|6|`TTM:TPL-+4`|返回 `TTM:OK`；已连接时应断开并重新广播|
|7|`TTM:ADP-10`|返回 `TTM:OK`，广播间隔为 1000 ms，复位后保持|
|8|`TTM:PID-1234`|返回 `TTM:OK`，广播厂商数据含 `FFFF3412`，复位后保持|
|9|`TTM:REN-?`|返回当前 `TTM:REN-名称`|
|10|`TTM:REN-TEST-C3`|返回 `TTM:OK`，重启扫描确认新名称|
|11|`TTM:MAC-?`|返回 12 位十六进制 MAC|
|12|`TTM:MAC-C2A1B2C3D4E5`|返回 `TTM:OK`，重启扫描确认 MAC；会永久改变身份地址|
|13|`TTM:ADD-?`|返回当前 `TTM:ADD-内容`|
|14|`TTM:ADD-ABC`|返回 `TTM:OK`，复位后查询确认保持|
|15|`TTM:CIT-100ms`|仅已连接时返回 `TTM:OK`，未连接时返回 `TTM:ERP`|

`TPL` 的 AT 协议流程已验证，但 ESP32-C3 当前控制器不提供运行时发射功率切换接口；实际射频功率应在控制器构建配置或目标移植平台上用射频仪表验证。

## 7. macOS 蓝牙与串口闭环测试

Mac mini 可直接使用内置蓝牙，无需 SSH 登录 Ubuntu：

```bash
cd apps/esp32-c3/function_test/macos_ble_test
bash ./build_macos_ble_test.sh
./macos_ble_test --serial /dev/cu.usbserial-xxxx
```

程序会生成 `macos_ble_test_record.md`，退出码为 0 表示全部自动项目通过。完整前提、接线和安全项目说明见 [macOS 测试说明](../function_test/macos_ble_test/README.md)。
